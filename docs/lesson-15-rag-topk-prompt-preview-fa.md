# درس ۱۵ — top-k و آماده‌کردن prompt در RAG

## هدف و منبع

این تمرین از ساختار [Phase 11, Lesson 06: RAG](https://github.com/rohitg00/ai-engineering-from-scratch/tree/main/phases/11-llm-engineering/06-rag) الهام گرفته است. بخش بازیابی را به انتخاب top-k chunkها و ساختن یک prompt preview وصل می‌کنیم. هیچ LLM یا API اجرا نمی‌شود.

## مدل ذهنی

جریان مفهومی این است:

`query -> retrieve -> augment prompt -> generate`

در این تمرین فقط تا انتهای **augment** جلو می‌رویم: چند chunk بالاتر امتیاز می‌گیرند، متن و URLشان وارد preview می‌شود، اما پاسخ تولیدی نداریم.

## ساختارهای مهم

- `scored_chunks` هر نتیجه را به شکل `(score, chunk)` نگه می‌دارد.
- `sort(key=lambda item: item[0], reverse=True)` نتیجه‌ها را بر پایه‌ی عضو اول یعنی score از بزرگ به کوچک می‌چیند.
- `top_k = 2` تعداد chunkهای انتخابی را تعیین می‌کند؛ `scored_chunks[:top_k]` فقط همان تعداد اول را برمی‌دارد.
- `source_line` URL و بخش را به متن همان chunk وصل می‌کند.
- `context` متن chunkهای منتخب را کنار هم قرار می‌دهد و داخل `prompt_preview` می‌رود.

## توضیح ساده‌ی خطوط کلیدی

1. `top_k = 2`: از فهرست مرتب‌شده، دو نتیجه می‌خواهیم.
2. `selected = scored_chunks[:top_k]`: دو عضو اول فهرست را انتخاب می‌کند؛ وقتی `top_k = 1` شد، فقط عضو اول می‌ماند.
3. `source_line = f"[Source: {chunk['url']} | Section: {chunk['section']}]"`: برای chunk فعلی خط منبع می‌سازد.
4. `context_parts.append(source_line + "\n" + chunk["text"])`: خط منبع و متن همان chunk را به context اضافه می‌کند.
5. `context = "\n\n".join(context_parts)`: chunkهای منتخب را با فاصله‌ی خالی از هم جدا می‌کند.
6. `prompt_preview` دستور، context و پرسش را کنار هم می‌گذارد؛ این فقط متن آماده است، نه یک فراخوانی مدل.
7. چاپ URL نشان می‌دهد metadata منبع از chunk همراه نتیجه بازیابی شده است.

## نتیجه‌ی واقعی کاربر

### اجرای اول: `top_k = 2`

انتخاب‌ها:

```text
admissions-0 score=0.994
deadlines-0 score=0.970
```

در prompt preview، متن و URL هر دو chunk دیده شد. کاربر درست پیش‌بینی کرد `admissions` اول و `deadlines` دوم می‌شود؛ اما اول انتظار داشت URL نیاید. بررسی کد روشن کرد URL داخل `source_line` ساخته و به `context` افزوده می‌شود.

### اجرای دوم: `top_k = 1`

انتخاب و preview فقط شامل `admissions-0` و URL پذیرش شد؛ `deadlines-0` و URL آن حذف شدند. کاربر درست پیش‌بینی کرد سند پذیرش می‌ماند و URL مهلت‌ها حذف می‌شود.

URLهای `university.example` ساختگی‌اند. بردارها نیز دستی‌اند؛ این دو اجرا فقط منطق top-k و پیوند metadata را نشان می‌دهند.

## محدودیت‌ها و خطاهای رایج

- `top_k` تعداد نتیجه‌هاست، نه حداقل کیفیت. با `top_k = 1` سامانه الزاماً یک نتیجه برمی‌گرداند، حتی اگر هیچ نتیجه‌ای واقعاً مرتبط نباشد.
- در اجرای اول chunk مهلت‌ها انتخاب شد، گرچه برای سؤال مدارک پذیرش مستقیماً پاسخ‌گو نبود؛ این نشان می‌دهد similarity همیشه با مرتبط‌بودن واقعی برابر نیست.
- دستور prompt به‌تنهایی تضمین نمی‌کند LLM فقط از منبع پاسخ دهد؛ باید خروجی را ارزیابی کرد و در نبود پشتوانه، abstain کرد.
- وجود URL در preview مفید است، اما URL ساختگی یا اشتباه citation معتبر ایجاد نمی‌کند.

## مرور پایان درس ۱۵

### خلاصه

- `top_k` تعداد chunkهای برترِ بازیابی‌شده را تعیین می‌کند.
- metadata منبع در preview همراه متن chunk می‌آید.
- `top_k = 2` دو chunk و `top_k = 1` فقط chunk اول را وارد preview کرد.
- Preview پاسخ LLM نیست؛ در این درس هیچ درخواست API ارسال نشد.
- top-k بدون threshold ممکن است نتیجه‌ی کم‌ربط را هم برگرداند؛ RAG واقعی به ارزیابی ارتباط، منابع معتبر و پاسخ «نمی‌دانم» نیاز دارد.

### خودآزمایی با پاسخ

1. در اجرای دوم چرا URL مهلت‌ها دیده نشد؟ **چون chunk مربوط به مهلت‌ها از top-1 حذف شد.**
2. آیا `top_k = 1` ثابت می‌کند نتیجه مرتبط است؟ **نه؛ فقط تعداد نتایج را محدود می‌کند.**
3. آیا prompt preview به معنی پاسخ مدل است؟ **نه؛ متن request را ساختیم اما آن را نفرستادیم.**
4. اگر بردارها و URL ساختگی باشند، آیا نتیجه citation واقعی است؟ **نه؛ برای Pathfinder باید منبع رسمی و واقعی را نگه داریم و بررسی کنیم.**
