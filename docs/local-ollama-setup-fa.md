# راه‌اندازی مدل محلی با Ollama

این راهنما حالت آفلاینِ شواهدی را به پاسخ‌گویی طبیعی‌تر با یک مدل روی همان رایانه تبدیل می‌کند. مدل به اینترنت برای پاسخ‌گویی نیاز ندارد؛ اما بار اول باید خود مدل را دانلود کنی. پرسش و بخش‌های بازیابی‌شده از فایل به Ollama محلی فرستاده می‌شوند، نه به یک سرویس ابری.

> **نکته‌ی مهم درباره‌ی Preview:** سرور Arena در محیطی جدا از ویندوز تو اجرا می‌شود و نمی‌تواند به `127.0.0.1` ویندوزت وصل شود. برای استفاده از Ollama محلی، هم Ollama و هم Local Research Agent را روی همان ویندوز اجرا کن. Preview می‌تواند بدون مدل در حالت Offline کار کند.

## ۱. نصب و دریافت مدل

Ollama را برای Windows از وب‌سایت رسمی نصب کن. سپس PowerShell را باز کن و این دستورها را اجرا کن:

```powershell
ollama --version
ollama pull qwen2.5:7b
ollama list
```

- `ollama --version` بررسی می‌کند Ollama نصب شده و در `PATH` قابل اجراست.
- `ollama pull qwen2.5:7b` مدل دارای پشتیبانی از ابزارها را دانلود می‌کند؛ دانلود اولیه چند گیگابایت است.
- `ollama list` نشان می‌دهد مدل دانلودشده در دسترس است.

اگر دستگاهت حافظه‌ی محدودی دارد، به‌جای `qwen2.5:7b` از `qwen2.5:3b` استفاده کن و همین نام را در `.env` هم وارد کن.

## ۲. تنظیم پروژه

در PowerShell وارد پوشه‌ی پروژه شو و فقط اگر `.env` نداری، نمونه را کپی کن:

```powershell
Set-Location "$HOME\Ai-Learning"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

- `Set-Location` وارد clone ویندوزی پروژه می‌شود.
- خط `if` وجود `.env` را بررسی می‌کند و فقط در صورت نبودنش `.env.example` را کپی می‌کند؛ بنابراین تنظیمات موجودت بازنویسی نمی‌شود.
- `notepad .env` فایل تنظیمات خصوصی همین پروژه را باز می‌کند.

در `.env` این تنظیمات را فعال یا اضافه کن. مقدار مدل باید با نامی که `ollama list` نشان داده یکی باشد:

```text
LOCAL_RESEARCH_LLM_BASE_URL=http://127.0.0.1:11434/v1
LOCAL_RESEARCH_LLM_MODEL=qwen2.5:7b
LOCAL_RESEARCH_LLM_API_KEY=
```

- خط اول آدرس رابط OpenAI-compatible محلی Ollama است.
- خط دوم نام مدلی است که Ollama دانلود کرده.
- خط سوم خالی می‌ماند؛ برای Ollama محلی معمولاً API key لازم نیست.

فایل `.env` در Git ثبت نمی‌شود. آدرس را به `0.0.0.0` تغییر نده؛ برنامه باید روی loopback محلی بماند.

## ۳. اجرای برنامه در همان ویندوز

اگر سرور برنامه‌ی قبلی هنوز در PowerShell اجراست، با `Ctrl+C` متوقفش کن. سپس در ریشه‌ی پروژه اجرا کن:

```powershell
.\.venv\Scripts\python.exe -m local_research_agent.server
```

این خط برنامه را روی همان رایانه‌ای اجرا می‌کند که Ollama روی آن در دسترس است. صفحه را در `http://127.0.0.1:8000` باز یا تازه‌سازی کن. وقتی Ollama پاسخ‌گو باشد، نشان بالای صفحه `Local model ready` را نمایش می‌دهد. بررسی وضعیت فقط به endpoint محلی `/models` درخواست می‌فرستد و متن سؤال یا فایل را ارسال نمی‌کند.

## ۴. آزمایش و رفع اشکال

با فایلی که در کتابخانه اضافه کرده‌ای، پرسشی بپرس که شواهدش در فایل وجود دارد. مدل می‌تواند متن روان‌تری بسازد، ولی ارجاع‌های خطی را همچنان باید بررسی کنی.

اگر نشانگر می‌گوید مدل در دسترس نیست:

1. با `ollama list` مطمئن شو مدل دانلود شده است.
2. بررسی کن Ollama در حال اجرا باشد؛ اگر لازم بود برنامه‌ی Ollama را باز کن.
3. مطمئن شو URL در `.env` به `http://127.0.0.1:11434/v1` و نام مدل درست است.
4. پس از تغییر `.env`، سرور Local Research Agent را متوقف و دوباره اجرا کن.

مدل محلی هم ممکن است کند باشد یا ادعایی بسازد که متن بازیابی‌شده پشتیبانی نمی‌کند. برنامه هم محدوده‌ی citation و هم تطابق محافظه‌کارانه‌ی واژه‌ها و عبارت‌ها را بررسی می‌کند و پاسخ ناسازگار را نمایش نمی‌دهد. این کنترل entailment معنایی را کامل ثابت نمی‌کند و ممکن است paraphrase درست را هم رد کند؛ متن نقل‌شده را بررسی کن. برای مدل دوردست، مسیر رضایت جداگانه باقی می‌ماند و بررسی وضعیت خودکار، سرویس دوردست را صدا نمی‌زند.
