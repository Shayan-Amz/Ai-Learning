# درس ۱۱ — از شناسه‌ی token تا بردار embedding

## هدف و جایگاه

بعد از تبدیل متن به token و ID، یک مدل زبانی برای هر ID بردار عددی می‌گیرد. این lookup یکی از قدم‌های ورودی مدل است. مثال این درس toy است؛ هیچ API یا مدل واقعی را اجرا نمی‌کند.

## مدل ذهنی

`ID -> embedding vector`

Embedding table را مثل یک جدول lookup در نظر بگیر: هر ID به یک فهرست عددی وصل است. در مدل واقعی، اعداد بردارها طی آموزش یاد گرفته می‌شوند. در این مثال، اعداد را دستی انتخاب کرده‌ایم تا ترتیب lookup دیده شود.

## کد اجرایی

فایل `embedding_lookup_demo.py` با کد ASCII:

```python
embedding_table = {
    1: [0.2, -0.1, 0.7],
    2: [0.0, 0.5, -0.3],
    3: [-0.4, 0.8, 0.1],
}

token_ids = [3, 2, 1]
vectors = [embedding_table[token_id] for token_id in token_ids]

for token_id, vector in zip(token_ids, vectors):
    print(f"ID {token_id} -> {vector}")
```

اجرا از PowerShell:

```powershell
.\.venv\Scripts\python.exe .\embedding_lookup_demo.py
```

## توضیح ساده و خط‌به‌خط

1. `embedding_table` یک dictionary برای lookup است.
2. هر کلید، یک token ID است؛ مثلاً کلید `3` به بردار `[-0.4, 0.8, 0.1]` وصل است.
3. بردارهای سه‌عددی این‌جا ساختگی و کوچک‌اند؛ در مدل واقعی معمولاً بردارها بُعدهای بسیار بیشتری دارند و از داده یاد گرفته می‌شوند.
4. `token_ids` ترتیب IDهایی را مشخص می‌کند که می‌خواهیم به بردار تبدیل کنیم.
5. list comprehension در `vectors` برای هر ID بردارش را از جدول می‌گیرد و ترتیب را حفظ می‌کند.
6. `zip` هر ID را کنار بردار متناظرش جفت می‌کند.
7. `print` هر جفت را در ترمینال نشان می‌دهد.

## نتیجه‌ی اجرای کاربر

کاربر پیش‌بینی کرد خط اول با ID `3` شروع می‌شود. خروجی واقعی:

```text
ID 3 -> [-0.4, 0.8, 0.1]
ID 2 -> [0.0, 0.5, -0.3]
ID 1 -> [0.2, -0.1, 0.7]
```

این ترتیب از `token_ids = [3, 2, 1]` می‌آید؛ هر ID بردار متناظر خودش را از `embedding_table` گرفت.

## نکته‌ی مهم برای ادامه

این **token embedding** داخلی مدل است: یک بردار برای هر token ID در مسیر ورودی LLM. در RAG هم معمولاً از **text embedding** برای نمایش یک متن/قطعه و جست‌وجوی معنایی استفاده می‌کنیم؛ این دو مفهوم مرتبط‌اند اما یکی نیستند.

## مرور پایان درس ۱۱

### خلاصه

- Token ID کلید lookup در embedding table است.
- مدل با بردارها کار می‌کند؛ شناسه‌ی عددی خودش embedding نیست.
- بردارهای این مثال دستی و ساختگی‌اند؛ بردارهای مدل واقعی آموخته می‌شوند.
- ترتیب بردارهای خروجی از ترتیب IDها در `token_ids` پیروی می‌کند.
- embedding ورودی token را با text embedding برای جست‌وجوی RAG اشتباه نگیریم.

### ساختارهای مهم

| ساختار | کاربرد |
|---|---|
| `embedding_table[token_id]` | گرفتن بردار مربوط به یک ID |
| `[embedding_table[id] for id in token_ids]` | تبدیل دنباله‌ی IDها به دنباله‌ی بردارها |
| `zip(token_ids, vectors)` | جفت‌کردن هر ID با بردارش |

### خودآزمایی با پاسخ

1. چرا خط اول خروجی مربوط به ID `3` بود؟ **چون `token_ids` با `3` شروع می‌شود و ترتیب حفظ می‌شود.**
2. آیا `[-0.4, 0.8, 0.1]` بردار واقعی یک مدل است؟ **نه؛ برای این مثال دستی انتخاب شده است.**
3. آیا token embedding با text embedding برای RAG یکی است؟ **نه؛ اولی lookup ورودی مدل است، دومی معمولاً برای بازیابی معنایی متن به کار می‌رود.**
