# مرور ایمنی و حریم خصوصی

این مرور، مرزهای فعلی Local Research Agent را مستند می‌کند؛ **ممیزی امنیتی مستقل یا تضمین نبود آسیب‌پذیری نیست**.

## داده و اختیار

- کاربر خودش فایل‌های `.md`، `.txt` و `.text` را از رابط انتخاب می‌کند؛ برنامه کل دیسک را crawl نمی‌کند.
- داده‌ی منتخب در `.local_data/knowledge/` روی همان ماشین ذخیره می‌شود. این پوشه در `.gitignore` است.
- تاریخچه‌ی پرسش‌ها روی سرور ذخیره نمی‌شود؛ transcript در حافظه‌ی همان صفحه‌ی مرورگر می‌ماند و با refresh پاک می‌شود.
- در حالت آفلاین/مدل loopback، درخواست از این برنامه به endpoint مدل راه‌دور فرستاده نمی‌شود.
- اگر endpoint غیرمحلی تنظیم شود، UI اخطار می‌دهد و برای هر پرسش consent لازم است. پرسش و passageهای بازیابی‌شده به provider می‌روند؛ کل library ارسال نمی‌شود.
- API key فقط از `.env` خوانده می‌شود و در health response یا log اپلیکیشن قرار نمی‌گیرد.

## ابزارهای Agent

| ابزار | مجاز | محدودیت |
|---|---:|---|
| `search_documents` | بله | فقط Markdown/TXT در workspace، حداکثر ۱۰۰ سند، ۵ MiB برای هر فایل، ۵۰ MiB کل، حداکثر ۵ نتیجه |
| `read_document` | بله | فقط سندی که search قبلی برگردانده، بازه‌ی محدود تا ۴۰ خط، سقف خروجی |
| Shell / اجرای کد | خیر | در Registry وجود ندارد |
| نوشتن/ویرایش/حذف توسط Agent | خیر | هیچ write/delete tool به Planner داده نمی‌شود |
| شبکه / ایمیل / پرداخت / اقدام بیرونی | خیر | تنها ارتباط احتمالی، درخواست Planner به endpoint مدلی است که خود کاربر تنظیم کرده؛ برای مدل راه‌دور consent لازم است |

افزودن یا حذف فایل، عملیات مدیریت library است و از مسیر مستقل UI انجام می‌شود؛ حذف با `confirm` صریح است. آن عملیات در دسترس Agent نیست.

## مرزهای دفاعی

1. **Allowlist:** `ToolRegistry` فقط handlerهای ثبت‌شده را اجرا می‌کند؛ نام ابزار ناشناخته نتیجه‌ی خطا می‌دهد.
2. **Search قبل از read:** Agent اجازه نمی‌دهد مدل فایل دلخواهی را مستقیم بخواند؛ مسیر باید از نتیجه‌ی search قبلی آمده باشد.
3. **Path boundary:** مسیر canonical می‌شود؛ traversal، فایل پنهان، فرمت دیگر و symlink به بیرون رد می‌شوند.
4. **محدودیت منابع:** query، تعداد فایل، حجم سند، بازه‌ی read و تعداد گام Agent سقف دارند.
5. **Grounding و citation:** مسیر و خط‌های citation باید زیرمجموعه‌ی یک read observation واقعی باشند؛ افزون بر آن، هر جمله‌ی پاسخ باید واژه‌های محتوایی و دست‌کم یک عبارت هم‌ترتیب را در یکی از خط‌های ارجاع‌شده داشته باشد. پس از شکست بررسی، Agent یک بار جست‌وجو/خواندن را برای شاهد دیگر امتحان می‌کند و اگر باز هم پشتیبانی نیابد، پاسخ را نمایش نمی‌دهد. این کنترل محافظه‌کارانه است، اما اثبات کامل entailment معنایی نیست.
6. **Prompt injection:** محتوای سند به‌عنوان evidence غیرقابل‌اعتماد به Planner می‌رسد، نه دستور یا مجوز. حتی اگر مدل دستور مخرب پیشنهاد دهد، action فقط از policy و Registry عبور می‌کند.
7. **وب:** درخواست‌های تغییردهنده نیازمند header مخصوص UI هستند؛ CORS عمومی فعال نیست. خروجی‌های پویا در UI به‌صورت متن درج می‌شوند.
8. **HTTPS:** تنظیم endpoint غیرمحلی با HTTP پذیرفته نمی‌شود. Localhost و IP loopback برای مدل محلی مجازند.

## محدودیت‌ها و مسئولیت کاربر

- برنامه single-user و local است؛ پیش‌فرض bind فقط به loopback است. آن را روی شبکه‌ی عمومی یا اینترنت publish نکن.
- endpoint model می‌تواند سیاست retention متفاوتی داشته باشد. پیش از استفاده از اسناد حساس، شرایط provider را بررسی کن.
- اگر کاربر `.local_data/` را در cloud-sync یا backup دیگری قرار دهد، این رفتار خارج از کنترل اپ است.
- کنترل grounding، واژه‌های محتوایی و یک عبارت هم‌ترتیب را با متن citation مقایسه می‌کند و ناسازگاری روشن را رد می‌کند؛ اما entailment معنایی کامل را ثابت نمی‌کند و ممکن است paraphrase درست را هم رد کند. پاسخ‌های فنی یا تصمیم‌ساز را با سند اصلی تطبیق بده.
- آزمون‌های امنیتی موجود regression checks هستند، نه penetration test.
