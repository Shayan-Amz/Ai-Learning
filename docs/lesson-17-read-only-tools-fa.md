# Lesson 17 — ساخت ابزارهای read-only برای فایل‌های محلی

## هدف

در Lesson 16 دیدیم که Agent یک `ToolCall` می‌سازد و Registry آن را اجرا می‌کند. این درس خود ابزارها را می‌خواند: جست‌وجوی خط‌های Markdown و خواندن چند خط اطراف نتیجه.

مرز ایمنی این مرحله روشن است: ابزار فقط به پوشه‌ای که هنگام ساخت به آن داده‌ایم دسترسی دارد، فقط `.md` می‌خواند، و هیچ ابزار shell/network/write ندارد.

## تمرین کوچک برای فهم مرز ابزار

1. در `local_research_agent/knowledge/safe-tool-use.md` واژه‌ی `approval` را جست‌وجو کن و ببین `line` چه عددی می‌شود.
2. تست مسیر `../private.md` را نگاه کن: کدام بررسی آن را رد می‌کند؟
3. نام `search_documents` را موقتاً از Registry حذف کن و تست `test_registry_refuses_unregistered_tools` را اجرا کن؛ پیش‌بینی کن پاسخ کدام قسمت عوض می‌شود. بعد تغییر آزمایشی را برگردان.

## مرور این درس

- هر tool یک تابع کوچک با ورودی/خروجی مشخص است؛ Registry فقط همین toolهای allowlist را اجرا می‌کند.
- `root.resolve()` و `is_relative_to(root)` مرز پوشه را اعمال می‌کنند.
- نتیجه‌ی search شامل path و line است؛ پاسخ نهایی می‌تواند به منبع قابل‌بررسی ارجاع دهد.
- خطای موردانتظار به observation تبدیل می‌شود؛ خطای برنامه‌نویسی را نباید بی‌صدا پنهان کرد.
- ابزارهای فعلی فقط read-only هستند؛ اضافه‌کردن write tool نیازمند policy و تأیید انسانی است.
- سؤال مرور: چرا چک‌کردن نام فایل با `startswith(root)` به‌تنهایی جای `resolve()` و `is_relative_to()` را نمی‌گیرد؟
