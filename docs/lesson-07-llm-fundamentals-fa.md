# درس ۷ — مدل زبانی بزرگ (LLM) چیست؟

## هدف و جایگاه در مسیر مرجع

پیش از صدا زدن مدل، باید تفاوت LLM، prompt، token، context window و Agent را بفهمیم. در این درس API key لازم نیست و هیچ درخواست بیرونی نمی‌فرستیم؛ فقط شکل پیام را می‌بینیم. این یک پل مقدماتیِ فارسی است؛ ادامه‌ی tokenization با الهام از [Phase 10, Lesson 01: Tokenizers](https://github.com/rohitg00/ai-engineering-from-scratch/tree/main/phases/10-llms-from-scratch/01-tokenizers) و سپس بخش‌های منتخب [Phase 11: LLM Engineering](https://github.com/rohitg00/ai-engineering-from-scratch/tree/main/phases/11-llm-engineering) پیش می‌رود.

## مدل ذهنی

یک LLM متن ورودی و زمینه‌ی قبلی را می‌گیرد و با پیش‌بینی token بعدی، متن را مرحله‌به‌مرحله تولید می‌کند. **Token لزوماً یک کلمه نیست**؛ ممکن است یک واژه، بخشی از واژه، نشانه یا واحدی دیگر باشد. در زبان‌هایی مثل فارسی، شمار token با تعداد واژه‌ها یکی نیست.

- **Prompt**: دستورها و پیام‌هایی که برای مدل می‌فرستیم.
- **Context window**: سقف tokenهایی که مدل می‌تواند در یک نوبت در نظر بگیرد؛ معمولاً prompt، history، context بازیابی‌شده و جواب تولیدی را شامل می‌شود. این همان حافظه‌ی دائمی نیست.
- **Temperature**: روی تصادفی‌بودن انتخاب خروجی اثر می‌گذارد؛ مقدار پایین‌تر معمولاً پاسخ را کم‌نوسان‌تر می‌کند، اما حقیقت یا دقت را تضمین نمی‌کند.
- **Hallucination**: متن روان و قانع‌کننده‌ای که ممکن است پشتیبانی منبع نداشته باشد یا غلط باشد.
- **Agent**: خودِ LLM نیست؛ برنامه‌ای است که می‌تواند از مدل، ابزارهای محدود، state و قواعد کنترل برای انجام وظیفه استفاده کند.

## یک payload نمایشی، نه درخواست واقعی

کد زیر فقط یک شکل متداولِ پیام‌های نقش‌دار را به JSON چاپ می‌کند. قالب دقیق API بین providerها فرق می‌کند؛ این کد درخواست نمی‌فرستد و به کلید نیاز ندارد.

در `llm_payload_demo.py` بنویس:

```python
import json

messages = [
    {
        "role": "system",
        "content": "فقط بر اساس context پاسخ بده؛ اگر کافی نیست، بگو نمی‌دانم.",
    },
    {
        "role": "user",
        "content": "Context: در این مثال فرضی، مهلت ۱۵ ژانویه است. سؤال: مهلت چیست؟",
    },
]

request_preview = {
    "messages": messages,
    "temperature": 0,
}

print(json.dumps(request_preview, ensure_ascii=False, indent=2))
```

اجرا در ترمینال VS Code:

```powershell
.\.venv\Scripts\python.exe .\llm_payload_demo.py
```

## کد چه می‌کند؟

1. `messages` فهرستی از دیکشنری‌هاست؛ هر دیکشنری یک پیام و نقش آن را نگه می‌دارد.
2. `system` رفتار موردانتظار را توضیح می‌دهد؛ `user` درخواست و context نمونه را می‌آورد.
3. `request_preview` تنظیمات را کنار پیام‌ها می‌گذارد؛ `temperature` فقط مثال آموزشی است و پارامتر همه‌ی APIها نیست.
4. `json.dumps` payload را به متن JSON تبدیل می‌کند.
5. `ensure_ascii=False` کمک می‌کند فارسی در خروجی خوانا چاپ شود؛ `indent=2` فقط فاصله‌گذاری نمایشی است.
6. چون در کد `urlopen`/`requests` نداریم، هیچ APIای صدا زده نمی‌شود.

## نکته‌های مهم

- context window محدود است؛ گفت‌وگوی طولانی یا اسناد بزرگ ممکن است از ظرفیت خارج شوند. Agent برای «حافظه‌ی دائمی» معمولاً به ذخیره‌سازی بیرونی نیاز دارد.
- Temperature کم، پاسخ را حقیقت‌سنجی نمی‌کند. برای سؤال‌های مهم، منبع و ارزیابی لازم داریم.
- system prompt کمک می‌کند رفتار مطلوب را توضیح دهیم، اما به‌تنهایی سد امنیتی قطعی نیست؛ متن مخرب، ابزارها و داده‌ها را باید جداگانه کنترل کنیم.

## تمرین

1. قبل از اجرا، حدس بزن چند پیام در JSON چاپ می‌شود و role هرکدام چیست.
2. متن context نمونه را طوری عوض کن که هیچ deadlineای نداشته باشد. بدون اجرای LLM، توضیح بده طبق system instruction پاسخ درست چه باید باشد.
3. با زبان خودت بگو چرا LLM به‌تنهایی حافظه‌ی دائمی یا تضمین صحت نیست.

## نتیجه‌ی اجرای کاربر

- پیش از اجرا درست پیش‌بینی کرد که payload دو پیام دارد: `system` و `user`.
- اجرای نخست JSON معتبر با همان دو پیام و `temperature: 0` چاپ کرد؛ فارسی خوانا بود.
- پس از حذف deadline از متن پیام `user`، خروجی دوباره همان ساختار JSON را داشت و متن جدید را نشان داد؛ مدل باز هم پاسخی تولید نکرد.
- در هیچ‌یک از دو اجرا درخواست API نفرستادیم.

## مرور پایان درس ۷

### موضوع و مدل ذهنی

LLM بر اساس متن ورودی، token بعدی را پیش‌بینی می‌کند. Token الزاماً یک کلمه نیست. Prompt پیام‌ها و دستورهایی است که به مدل می‌دهیم؛ context window سقف محتوایی است که مدل در یک نوبت می‌تواند در نظر بگیرد، نه حافظه‌ی دائمی. Agent برنامه‌ای پیرامون مدل است و می‌تواند با ابزارهای محدود و قواعد توقف کار کند.

### کدها و ساختارهای مهم

| کد/ساختار | کاربرد |
|---|---|
| `messages` با `role`های `system` و `user` | مرتب‌کردن دستور و درخواست در قالب پیام‌های نقش‌دار؛ شکل دقیق به API provider بستگی دارد. |
| `json.dumps(data, ensure_ascii=False, indent=2)` | تبدیل ساختار Python به JSON خوانا؛ متن فارسی را بدون escape چاپ می‌کند و خروجی را مرتب می‌سازد. |
| `temperature: 0` | نمونه‌ی یک تنظیم برای کاهش تصادفی‌بودن در APIهایی که پشتیبانی‌اش می‌کنند؛ صحت را تضمین نمی‌کند و کد نمایشی هم آن را اجرا نمی‌کند. |
| `python.exe .\\llm_payload_demo.py` | اجرای محلی اسکریپت؛ این نسخه فقط payload را چاپ می‌کند و شبکه را صدا نمی‌زند. |

### خطاهای مفهومی رایج

- دیدن JSONِ درخواست را با دیدن پاسخ واقعی LLM اشتباه نگیریم.
- `temperature` پایین را با حقیقت‌سنجی یکی ندانیم.
- context window را با حافظه‌ی دائمی Agent اشتباه نگیریم.
- وجود دستور «اگر نمی‌دانی، بگو نمی‌دانم» تضمین قطعی نیست؛ در کاربرد واقعی باید رفتار را آزمایش و ارزیابی کرد.

### خودآزمایی با پاسخ کوتاه

1. آیا token همیشه یک واژه‌ی کامل است؟ **نه.**
2. چرا اسکریپت جواب deadline را نداد؟ **چون فقط `json.dumps` اجرا شد؛ هیچ درخواست مدل نفرستادیم.**
3. آیا `temperature: 0` درستی را تضمین می‌کند؟ **نه؛ فقط روی تصادفی‌بودن اثر می‌گذارد و رفتار دقیق به provider وابسته است.**
4. آیا context window حافظه‌ی دائمی است؟ **نه؛ محدودیت محتوای قابل‌استفاده در یک نوبت است.**
