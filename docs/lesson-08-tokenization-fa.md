# درس ۸ — کلمه، نویسه و token یکی نیستند

## هدف و جایگاه در مسیر مرجع

این درس، بخش مقدماتیِ [Phase 10, Lesson 01: Tokenizers](https://github.com/rohitg00/ai-engineering-from-scratch/tree/main/phases/10-llms-from-scratch/01-tokenizers) را برای کاربرد LLMها جدا می‌کند. هدف، ساخت tokenizer کامل یا آموزش مدل نیست؛ فعلاً فرقِ جداکردن بر اساس فاصله، طول رشته‌ی Python و tokenهای مدل را روشن می‌کنیم.

## مدل ذهنی

متن معمولی باید پیش از ورود به مدل به شناسه‌های عددی تبدیل شود. tokenizer این تبدیل را انجام می‌دهد. یک token ممکن است واژه‌ی کامل، بخشی از واژه، نشانه یا واحدی دیگر باشد. مرز tokenها را از روی تعداد فاصله‌ها یا حروف نمی‌توان دقیق فهمید؛ tokenizerهای مدل‌های مختلف هم می‌توانند متفاوت باشند.

## کد آزمایش

در `tokenizer_basics.py`:

```python
text = "مهلت چیست؟"

parts = text.split()

print(parts)
print("بخش‌های جداشده با فاصله:", len(parts))
print("طول رشته در Python:", len(text))
```

اجرا در PowerShell، از پوشه‌ی تمرین:

```powershell
.\.venv\Scripts\python.exe .\tokenizer_basics.py
```

## توضیح کد

- `text.split()` رشته را در فاصله‌ها می‌شکند و یک list برمی‌گرداند. برای این جمله دو عضو دارد: `مهلت` و `چیست؟`. علامت سؤال به همان عضو دوم چسبیده است؛ پس این‌ها بخش‌های جداشده با فاصله‌اند، نه یک tokenizer زبانی عمومی.
- `len(parts)` تعداد عضوهای list را می‌شمارد؛ این‌جا `2`.
- `len(text)` طول رشته را بر حسب code pointهای Unicode در Python می‌دهد؛ در این مثال `10`، شامل حروف، فاصله و علامت سؤال. در متن‌های دارای نویسه‌های ترکیبی، code point و چیزی که چشم یک نویسه می‌بیند همیشه یکی نیستند؛ فعلاً همین تمایز را می‌دانیم.
- هیچ‌کدام از این دو شمارش تعداد tokenهای مدل را نمی‌دهد. تعداد دقیق فقط با tokenizer مربوط به همان مدل/سرویس یا گزارش usage خودش معلوم می‌شود.

## نتیجه‌ی واقعی کاربر

خروجی:

```text
['مهلت', 'چیست؟']
بخش‌های جداشده با فاصله: 2
طول رشته در Python: 10
```

کاربر درست پیش‌بینی کرد: یک فهرست دو عضوی، تعداد دو بخشِ جداشده با فاصله و طول ده code point.

## مرور پایان درس ۸

### خلاصه

- `text.split()` → فهرستی از بخش‌های جداشده با whitespace، نه tokenهای مدل.
- `len(text.split())` → تعداد همان بخش‌ها.
- `len(text)` → طول رشته در Python بر حسب Unicode code point، نه token مدل.
- tokenization → تبدیل متن به واحدها/شناسه‌هایی که tokenizer مدل تعریف کرده است؛ مرز آن‌ها را نباید از روی فاصله حدس زد.

### خطاهای رایج

1. یکی گرفتن `split()` با tokenizer واقعی.
2. فرض این‌که هر کلمه دقیقاً یک token است.
3. فرض این‌که شمارش token در مدل‌ها یا زبان‌های مختلف یکسان است.

### خودآزمایی

1. آیا `len(text.split())` تعداد token مدل را می‌دهد؟ **نه؛ فقط تعداد بخش‌های جداشده با فاصله را می‌دهد.**
2. این‌جا چرا `len(text)` برابر ۱۰ است؟ **چهار حرف در «مهلت»، یک فاصله، چهار حرف در «چیست» و یک علامت سؤال.**
3. برای دانستن تعداد token واقعی چه لازم است؟ **Tokenizer همان مدل یا مقدار usage گزارش‌شده از سرویس.**

**گام بعدی:** از همان مسیر مرجع سراغ ایده‌ی subword و یک نمایش کوچک از BPE می‌رویم؛ آن مثال toy خواهد بود و ادعای شمارش tokenهای یک API واقعی نمی‌کند.
