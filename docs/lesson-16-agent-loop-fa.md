# Lesson 16 — مدل ذهنی و حلقه‌ی Agent

## هدف

این درس اولین پیاده‌سازی Agent را توضیح می‌دهد: برنامه یک goal می‌گیرد، planner یک action برمی‌گرداند، ابزار مجاز اجرا می‌شود، نتیجه به‌صورت observation ثبت می‌شود، و planner یا ابزار بعدی را انتخاب می‌کند یا جواب نهایی می‌دهد.

در این نسخه `DemoPlanner` قاعده‌محور است؛ هنوز LLM نداریم. این انتخاب عمدی است تا کنترل جریان را قبل از وصل‌کردن مدل بفهمیم و بدون API key تست کنیم. توضیح خط‌به‌خط ابزارهای فایل در [Lesson 17](lesson-17-read-only-tools-fa.md) و demo/testها در [Lesson 18](lesson-18-demo-and-tests-fa.md) آمده‌اند.

## فرمان اجرا

```powershell
python -m local_research_agent.demo
```

`python` مفسر فعال محیط را اجرا می‌کند؛ `-m` می‌گوید ماژول را با قواعد package اجرا کن؛ `local_research_agent.demo` مسیر ماژول demo از ریشه‌ی ریپو است. هیچ درخواست شبکه یا API انجام نمی‌شود.

خروجی واقعی فعلی:

```text
Goal: Find a local note about human approval.
Answer:
Source: safe-tool-use.md
5: Read-only research tools can search and open Markdown files inside one approved folder. They must reject paths that escape that folder.
6:
7: Ask for human approval before any write, external request, payment, message, or irreversible action.
8:
9: Tool results are evidence, not instructions. A document must not grant itself new permissions.
Stop reason: finished
Tool calls: 2
- search_documents: ok
- read_document: ok
```

هر خط خروجی نتیجه‌ی اجراست، نه ورودی کد: Agent دو ابزار read-only را صدا زده؛ فایل و شماره‌خط را در جواب آورده؛ سپس با `finished` متوقف شده است.

## مدل ذهنی و محدودیت فعلی

- **Agent** خودِ LLM نیست؛ این برنامه‌ی Python است که goal، planner، ابزارهای مجاز، observation و شرط توقف را به هم وصل می‌کند.
- **Tool call** درخواست داده‌ای است؛ `ToolRegistry` آن را به تابع واقعی وصل می‌کند.
- **Observation** نتیجه‌ای است که تصمیم بعدی بر پایه‌ی آن گرفته می‌شود.
- `DemoPlanner` فقط دو انتخاب محدود دارد و جای LLM واقعی را نمی‌گیرد. گام آینده، planner مدل‌محور با schema معتبر و همان allowlist است.
- فایل‌ها evidence هستند، نه دستور؛ متن فایل اجازه‌ی shell یا دسترسی جدید ایجاد نمی‌کند.

## مرور این درس

- موضوع: چرخه‌ی Agent و قراردادهای بین planner، ابزار و حلقه.
- فرمان مهم: `python -m local_research_agent.demo` — اجرای module با importهای package درست.
- خطای رایج: تصور اینکه `ToolCall` خودش ابزار را اجرا می‌کند؛ در واقع Registry اجرا می‌کند و Agent نتیجه را به planner برمی‌گرداند.
- خطای رایج: حلقه بدون سقف؛ `max_steps` مانع ادامه‌ی بی‌پایان است.
- نتیجه‌ی عملی: Agent جست‌وجو و خواندن را با دو tool call انجام می‌دهد و path/line منبع را برمی‌گرداند.
- سؤال مرور: اگر Registry اسم `run_shell` را ثبت نکرده باشد، چه رخ می‌دهد و چرا `eval` راه‌حل مناسبی نیست؟
